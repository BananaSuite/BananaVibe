# Code of Conduct

BananaVibe writes code that a person then has to review. Most of what gets
discussed here is about where that line sits.

What is expected:

- Keep criticism on the patch rather than on its author.
- When reporting a bad run, include the configuration and the step that failed.
  Redact issue content, tokens and share links first.
- Do not argue for removing the review gate. A draft pull request that a human
  reads is the point of the project.
- Say when a diff came from an agent. Reviewers weigh it the same either way,
  but they should not have to guess.

What is not acceptable: harassment, personal attacks, sustained disruption, or
publishing someone's private information, including issue content from a
private forge.

Comments that are no longer about the software may be hidden or removed, a
thread may be locked, and an account that keeps going may be blocked.

Write to [Luca Zani (OverloadedTech)](https://github.com/OverloadedTech) using
the contact details on that profile if something here needs attention. Keep
suspected vulnerabilities out of public threads and use the private route in
[SECURITY.md](SECURITY.md).
